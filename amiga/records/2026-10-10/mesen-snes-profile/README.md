# SNES complete-frame stage profiling, 10 October 2026

[Method/build instructions](../../../mesen_snes/system/PROFILING.md) and
[interpretation](../../../mesen_snes/README.md#physical-profiling-results-10-october-2026).

Physical A4000TX / ZZ9000 Core1 / XX19c with the same XACP launch, 4 MiB owned
allocation and private-L1/outer-NC mapping as the verified system milestone.
All workloads use the original six-frame Mode 0 startup fixture and silent DSP.
No RTG output, audible playback or external game ROM is involved.

| Configuration | Mean time per frame | Result |
| --- | ---: | --- |
| Original uninstrumented System | 40.698 ms | Passed |
| Profile, PPU -Os | 40.797 ms | Passed |
| Profile, PPU -O2 | 40.705 ms | Passed; no meaningful gain |

Each mean is from ten batches after one warmup, six frames per batch. The first
partial startup frame is included. Initialization, validation and destruction
are outside the ARM timer. PPU/SPC scopes are nested exclusive measurements;
the residual includes CPU/bus/IRQ scheduling, test loop and remaining profiler
cost. Instrumentation and code layout can perturb each stage. The alternative
compiler setting fits but does not solve the performance problem.

Baseline profile shares: PPU 49.82%, SPC/DSP 15.74%, residual 34.44%.
Even excluding PPU cost leaves about 20.47 ms, above the roughly 16.6 ms NTSC
budget. This bounds this measured workload, not arbitrary games. No measured
game/display FPS is claimed. Finer graphics and scheduling profiling are next.

`results.json` is generated by `scripts/analyze_mesen_snes_profile.py`, which
rejects incorrect signatures, malformed samples, missing cancellation, mismatched
register restoration and inconsistent stage totals. Logs retain all raw samples.
Native ASan/UBSan 60-frame output is unchanged from the system milestone.
Both A9 model runs per build use a synthetic timer, validate separate load
addresses, corruption rejection and cancellation; they do not model caches.
The native profile unit test covers nested scopes, disabled timing and wrap.
Common ARM regression and MCP smoke suites pass. Physical logs verify RET1,
all 14 saved registers, cache/MMU witness and release; no crash/reboot observed.
